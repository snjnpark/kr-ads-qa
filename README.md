# kr-ads-qa

광고 설정을 한국어로 검색하고 예산·일정·운영 정책을 점검합니다. 하나의 소스로 **Vercel 웹 서비스**와 **로컬 셀프 호스팅**을 지원합니다. 어느 방식이든 광고 데이터의 저장·검색·QA·이력·자연어 모델 실행은 사용자 브라우저에서 처리합니다.

## 시작하기

셀프 호스팅에는 Node.js **24.10 이상 24.x**와 Git이 필요합니다.

```sh
git clone https://github.com/snjnpark/kr-ads-qa.git
cd kr-ads-qa
npm ci
npm run build
npm start
```

[http://127.0.0.1:8080](http://127.0.0.1:8080)을 열고 **설정 → 광고 API 연결**에서 인증 정보를 입력합니다. 서버 재시작 없이 이 탭에서 연결됩니다. 코드를 수정하며 실행하려면 `npm run dev`를 사용합니다.

Vercel에서는 이 저장소를 Import하고 Next.js, Node.js 24.x, 빌드 명령 `npm run build`를 사용합니다. 설정은 [vercel.json](vercel.json)에 포함되어 있습니다. API 키를 Vercel 환경변수에 등록하지 않습니다. HTTPS로 제공해야 하며, 원격 셀프 호스트는 리버스 프록시 뒤에서 `LAYA_PUBLIC_ORIGIN=https://실제도메인`을 지정합니다. 로컬 설정 예시는 [.env.example](.env.example)을 참고하세요.

## 데이터와 인증 정보

| 처리 | 위치 |
|---|---|
| 광고 데이터·정책·검색/QA 기록·스냅샷 | 이 브라우저의 IndexedDB |
| 검색·QA·비교·자연어 모델 | 이 브라우저의 Worker |
| API 인증 정보 | 현재 탭의 메모리; 새로고침·종료 후 다시 입력 |
| CSV·백업·모델 파일 가져오기 | 이 브라우저에서 파일 생성·읽기 |
| Meta·Google Ads·카카오모먼트 API | 브라우저에서 매체로 직접 요청 |
| 네이버 검색광고·카카오 키워드광고 API | 같은 출처의 읽기 전용 서버 중계를 일시 경유 |

**서비스는 중계한 광고 데이터와 인증 정보를 서버에 저장하거나 수집하지 않습니다.** 중계 서버는 허용된 조회 한 건을 전달하며, 앱 DB·파일·캐시·작업 큐·본문 로그를 만들지 않습니다. 네이버 비밀 키는 브라우저에서 서명할 때 사용하고 서버로 보내지 않습니다. 카카오 키워드광고 토큰과 중계 응답은 처리 중 서버 메모리를 일시 경유합니다.

`no-store`는 서버가 데이터를 전혀 접하지 않는다는 뜻은 아닙니다. Vercel·프록시·매체·모델 파일 호스트의 접속 기록이나 인프라 보관 정책까지 0으로 보장하지 않습니다. 운영자는 요청/응답 본문·인증 헤더를 수집하는 분석·APM·Log Drain을 연결하지 않아야 합니다. 기본 앱에는 광고 데이터 업로드·서버 보관·분석 전송 기능이 없습니다.

브라우저 저장은 기기·브라우저·접속 주소마다 분리됩니다. Vercel 주소와 localhost는 서로 다른 데이터 공간입니다. 브라우저 데이터 삭제·비공개 모드·저장 공간 회수로 데이터가 사라질 수 있으므로 **설정 → 조회·이력 → 백업 다운로드**로 보관하세요. 백업은 인증 정보를 포함하지 않지만 광고 데이터 자체를 포함하므로 직접 관리해야 합니다. 다른 주소에서는 백업 파일로 옮깁니다. 기존 Node 앱의 SQLite·OS 인증 저장소는 자동으로 읽거나 이전하지 않습니다.

## 모델 준비

별도 AI API 키는 필요하지 않습니다. 원본 학습 모델 약 **1.35GB**와 브라우저 메모리·저장 공간이 필요합니다. 최신 데스크톱 Chromium에서 실제 WASM 실행을 검증했습니다. 준비 후 공개 모델만 CacheStorage/OPFS에 보관하고 재실행 때 크기·SHA-256을 다시 확인합니다.

현재 GitHub Release는 브라우저 자동 다운로드에 필요한 CORS 헤더를 제공하지 않습니다. **설정 → 모델 실행**에서 [고정 모델 릴리스](https://github.com/snjnpark/kr-ads-qa-models/releases/tag/model-conditions-v1)의 다음 7개 파일을 다운로드한 뒤 함께 선택해 가져오세요. 파일은 서버에 업로드하지 않습니다.

```text
laya.onnx
laya_config.json
tokenizer--tokenizer.json
tokenizer--tokenizer_config.json
model.onnx.data
condition-head.onnx
candidate-manifest.json
```

자동 준비를 제공하려면 같은 파일을 공개 CORS 호스트에 올리고 **빌드 전에** `NEXT_PUBLIC_LAYA_MODEL_BASE_URL`을 지정합니다. 파일 내용은 고정된 해시와 일치해야 합니다. 모델은 광고 중계 서버를 통해 다운로드하지 않습니다. WASM 실행 파일은 고정 npm 의존성에서 준비해 같은 출처로 제공합니다.

## 지원 범위와 사용 방법

Meta, 네이버 검색광고, Google Ads, 카카오모먼트, 카카오 프리미엄링크 키워드광고를 조회합니다. GFA·키워드광고 톡채널검색·별도 Google 광고 제품은 연결하지 않습니다. API는 읽기 전용이며 광고를 생성·수정·삭제하지 않습니다. 인증·권한·API 승인·쿼터에 따라 조회 범위가 달라집니다. Google은 사용자 액세스 토큰과 필요한 경우 관리자 계정 ID를 입력합니다. 토큰 자동 갱신이나 서버 측 OAuth 비밀 키 보관은 제공하지 않습니다.

1. 설정에서 필요한 매체의 인증 정보를 이 탭에 연결합니다.
2. 매체·계정·상품 범위를 선택하고 데이터를 새로고침합니다.
3. 설정 검색에 `메타에서 하루 예산이 5만 원 미만인 캠페인 찾아줘`처럼 질문합니다.
4. 운영 정책을 저장하고 현황에서 선택해 전체 QA를 실행합니다.
5. 변경 이력에서 스냅샷을 저장·비교하고 결과를 CSV로 내려받습니다.

불완전한 수집은 정상 수집본과 구분하고 이전 완료 데이터를 유지합니다. 지원하지 않거나 불명확한 질문은 보류할 수 있습니다. 결과의 근거·조회 범위·확인 불가 항목을 함께 확인하세요. 브라우저 직접 호출이 매체 정책·CORS로 차단되면 오류를 표시하며 자동으로 서버 중계 범위를 넓히지 않습니다.

## 개발·배포 경계

공개 Git에는 프로덕션 소스와 필수 빌드·배포 설정을 제공합니다. 개발 문서·AGENTS.md·테스트·합성 데이터·학습/평가 도구·이전 Node 실행 코드는 개발자 로컬에 반드시 보존하면서 Git에서 제외합니다. 공개 clone에는 포함되지 않습니다. 개발자 로컬의 `npm run dev:test`와 `npm run test:e2e`는 API 없이 합성 데이터·테스트 해석기로 실행하며 별도 작업 폴더·브라우저 DB를 사용합니다. 공개 프로덕션 빌드에는 테스트 모드 전환 기능이 없습니다.

`.gitignore`와 `.vercelignore`가 소스 업로드를 제외하며, `npm run build`는 테스트 표시·네이티브 DB/모델 코드·개발 자료가 브라우저 번들과 서버 의존성 추적에 없는지도 검사합니다. Git 제외는 이미 공개된 과거 커밋을 지우지 않습니다. 사용자 데이터·비밀값·모델 가중치는 커밋하지 않습니다.

로컬 Windows/Chromium에서 공개 파일만 복사한 운영 빌드·브라우저 동작·모델 실행을 검증했습니다. 실제 광고 계정 인증·CORS·쿼터와 원격 Vercel 서비스 운영 검증은 별도로 필요합니다.
