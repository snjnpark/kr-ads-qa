# kr-ads-qa

광고 설정을 한국어로 검색하고, 예산·일정·운영 정책을 점검하는 로컬 앱입니다. Meta, 네이버 검색광고 전상품, 카카오모먼트, 카카오 프리미엄링크 키워드광고, Google Ads를 지원합니다. GFA·키워드광고 톡채널검색·별도 Google 광고 제품은 연결하지 않습니다.

광고 매체의 API를 연결하면 계정의 캠페인·광고그룹·광고 설정을 불러옵니다. 자연어로 질문해 필요한 설정을 찾고, 예산·일정·운영 정책에 맞는지 QA 결과와 근거를 확인할 수 있습니다.

## 시작하기

**Node.js 24.10 이상**과 Git을 설치한 뒤 터미널에서 실행하세요. Windows에서 실행을 검증했습니다.

```sh
git clone https://github.com/snjnpark/kr-ads-qa.git
cd kr-ads-qa
npm ci
npm run dev
```

브라우저에서 **[http://127.0.0.1:8080](http://127.0.0.1:8080)**을 엽니다. 종료하려면 터미널에서 `Ctrl+C`를 누릅니다.

자연어 QA를 처음 사용할 때 [최종 학습 모델](https://github.com/snjnpark/kr-ads-qa-models/releases/tag/model-conditions-v1)을 자동으로 다운로드합니다. 약 **1.35GB**의 다운로드와 저장 공간이 필요하며, 준비가 끝날 때까지 기다려 주세요. 이후에는 저장된 모델을 재사용합니다. 직접 학습하거나 GitHub에 로그인할 필요가 없습니다.

질문 해석은 로컬 CPU에서 실행하므로 별도의 AI API 키나 GPU는 필요하지 않습니다.

## 할 수 있는 일

| 기능 | 사용 방법 |
|---|---|
| 설정 검색 | 한국어로 예산·상태·이름·날짜 조건을 입력해 광고 설정을 찾습니다. |
| 전체 QA | 현황에서 운영 정책을 선택해 불러온 광고 설정을 검사하고 위반 내용과 근거를 확인합니다. |
| 운영 정책 | 일예산·운영 상태 등 공통 조건과 매체별 조건을 작성하고 정책을 저장·불러옵니다. |
| 변경 이력 | 현재 설정의 스냅샷을 저장하고 이전 상태와 비교합니다. |
| 자연어 초안 | 정책 편집기에서 자연어로 조건 초안을 만들고 확인·수정한 뒤 같은 정책에 추가합니다. |
| 결과 내보내기 | 조회·검수 결과를 CSV로 저장합니다. |

설정 검색에서 다음과 같이 질문할 수 있습니다.

- `캠페인 예산 설정 안 된 캠페인 찾아줘`
- `메타에서 하루 예산이 5만 원 미만인 캠페인 찾아줘`
- `운영 중이고 하루 예산이 8만5천 원 이하인 캠페인 찾아줘`
- `이름에 '여름'이 포함된 캠페인 찾아줘`

운영 정책에서 정상으로 판단할 조건값과 검사 대상을 설정합니다. 예를 들어 공통 일예산 상한을 5만 원으로 정하고, 메타에는 별도 상한과 오디언스 필수 조건을 추가할 수 있습니다. 같은 항목·비교·검사 대상의 매체별 조건은 공통 조건보다 우선하며, 조건부 검사는 각각 실행합니다.

정책을 저장한 뒤 **현황**에서 선택하고 **전체 QA 실행**을 누릅니다. 결과에는 적용한 정책 버전과 실제 값·기대 조건·조회 근거가 기록됩니다. 조회되지 않은 값은 확인 불가, 매체에서 지원하지 않는 값은 해당 없음으로 구분합니다. 저장 전 편집 내용은 검사에 적용되지 않습니다.

자연어 초안은 일예산 금액 비교·운영 상태·종료일·승인 오디언스에 대한 정해진 표현을 지원합니다. 한 번에 한 조건을 입력하고 생성된 항목·검사 대상·비교 값을 확인하세요. 정책 이름을 입력하고 검사할 항목을 켠 뒤 기준값을 정하세요. 운영 상태는 ‘운영 중’ 또는 ‘일시중지’로 선택할 수 있습니다. 저장한 정책은 ‘정책 불러오기’에서 다시 열고, ‘저장 버전 보기’에서 이전 기준을 확인합니다. 이전 형식의 정책은 조회용으로 보존하며, 새 정책에서 검사 기준을 정해 저장할 수 있습니다.

API를 연결하기 전에는 광고 데이터가 표시되지 않습니다.

질문이 모호하거나 지원하지 않는 요청이면 조건을 더 구체적으로 입력하라는 안내가 표시됩니다. 검색·검수 결과에는 확인하지 못한 항목이 포함될 수 있으므로 근거와 조회 범위도 함께 확인하세요.

## 광고 API 연결과 QA

1. **설정 → 광고 API 연결**에서 매체를 선택하고 인증 정보를 저장합니다. Google은 OAuth 인증 또는 액세스 토큰 방식을 선택할 수 있습니다.
2. 서버를 종료하고 `npm run dev`로 다시 실행합니다.
3. 조회할 매체와 계정을 선택하고 데이터를 새로고침합니다.
4. **설정 검색**에 자연어 질문을 입력해 광고를 찾습니다.
5. **운영 정책**에서 검사 조건을 저장한 뒤 **현황**에서 정책을 선택하고 **전체 QA**를 실행합니다.

인증 정보는 OS 인증 저장소에 보관됩니다. 매체별 API 인증정보와 조회 권한을 준비하고 설정 화면의 해당 매체 연결 항목에 입력하세요. 광고 계정에 부여된 권한과 매체 API가 제공하는 범위만 조회합니다.

설정의 **조회·이력**에서 데이터 재사용 시간, 자동 저장 간격, 기준 시간대를 변경합니다. **모델 실행**에서는 시작 시 모델을 미리 불러오도록 설정할 수 있습니다. 환경 설정은 저장 후 앱을 다시 실행하면 적용되며, 화면에서 현재 적용 중인 값과 재시작 대기 상태를 확인할 수 있습니다. 조회 데이터 비우기는 임시 데이터만 지우며 저장한 정책과 검사·변경 이력은 유지합니다.

광고 API는 **읽기 전용**입니다. 이 앱에서 광고를 생성·수정·삭제하지 않습니다. 계정별 인증과 권한에 따라 조회 가능한 범위가 달라집니다. 매체가 제공하는 원본 변경 로그는 Meta·Google에서 일부 지원합니다.

## 소스 수정과 운영 실행

이 저장소에는 수정 가능한 프론트엔드·백엔드 소스와 필수 실행 설정을 배포합니다. 개발·검증 문서, 테스트, 합성 더미 데이터, 파인튜닝/평가 자료, QA 결과와 빌드 산출물은 현재 파일 구성에서 제외합니다. 공개 Git 이력은 현재 애플리케이션 소스부터 시작하며 과거 테스트·학습 자료의 이력은 포함하지 않습니다.

`npm run dev`는 실제 광고 API를 사용하는 앱 하나를 `127.0.0.1:8080`에서 실행합니다. 더미 모드나 별도 테스트 앱은 제공하지 않습니다. 코드를 수정하면 개발 서버가 변경을 반영합니다.

최적화한 운영 실행이 필요하면 다음 명령을 사용하세요.

```sh
npm run typecheck
npm run build
npm start
```

Node.js24.10.0 이상이 필요합니다. 환경변수 예시는 `.env.example`을 참고하고 비밀값을 Git에 넣지 마세요. 설정·DB·사용자 정책·모델 캐시는 실행 후 로컬에 생성되며 Git에서 제외됩니다. 모델 다운로드 실패 시 네트워크와 저장 공간을 확인하고 다시 실행하세요. 모델 가중치는 소스 저장소에 포함하지 않습니다.
